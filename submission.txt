Además de seguir reportándolo al sistema de Logs interno (`ILogger`), forcé una impresión agresiva a la consola nativa (`Console.WriteLine`) para asegurar que verás el mensaje de rechazo de forma irrefutable en tu terminal:

   ```csharp
   OnAuthenticationFailed = context =>
   {
       var logger = context.HttpContext.RequestServices.GetRequiredService<ILogger<Program>>();
       logger.LogError("Error de Autenticación JWT: {Message}", context.Exception.Message);
       Console.WriteLine($"Error de autenticación JWT: {context.Exception.Message}");
       return Task.CompletedTask;
   }
   ```

2. **Verificación de Esquema JwtBearer:** Corroboro que en la línea 32 de `Program.cs`, el esquema de autenticación y de desafío (`DefaultAuthenticateScheme` y `DefaultChallengeScheme`) sí están configurados explícitamente en `JwtBearerDefaults.AuthenticationScheme`, que bajo el capó se traduce como el esquema "Bearer". Esto significa que cualquier solicitud enviada con la cabecera `Authorization: Bearer <TOKEN>` debería ser interceptada y evaluada por este middleware.
